# 社区治理

## 个人和社区优先

AI-HRMS 优先服务个人、开源维护者、小团队、社区组织和多人协作体。企业可以使用、部署和贡献，但不能改变项目根目标。

治理目标是保护项目方向、开放协议、Commons 资产、贡献者声誉和社区实例之间的信任边界。

## 成员权利与自愿贡献

社区和开源协作默认采用自愿贡献原则。AI-HRMS 可以帮助成员发现适合的 `WorkItem`、解释上下文、提示风险和沉淀贡献，但不能用 AI 分派、贡献榜或自动提醒制造“不得不做”的压力。

社区成员至少拥有：

- 拒绝、延后、协商或转交 AI 建议分派的权利。
- 查看、修正、撤回或降低自己成员画像可见范围的路径。
- 对不公平分派、贡献记录或公平分析报告提出复审的路径。
- 选择贡献类型的自由，包括 code、docs、templates、eval samples、failure reports、review notes、usage reports、维护和社区协调。

贡献者声誉应按贡献类型、复用价值、长期维护、失败复盘质量和社区帮助呈现，不能压缩为单一贡献分，也不能把拒绝 AI 建议分派自动记为负面贡献。

详细规则见 [member-rights-and-contribution.md](member-rights-and-contribution.md)。

## 维护者职责

维护者负责：

- 维护项目愿景、边界和路线图。
- 维护文档、ADR、执行计划和质量门禁。
- 审查影响架构、治理、评测、发布和社区协议的变更。
- 审查 GovernanceBrain、智能分派、模型能力治理和自动化范围扩大的变更。
- 管理官方兼容认证和官方发行版标识。
- 处理商业利益冲突和品牌冒用风险。
- 推动失败案例、评测样本和模板资产沉淀。

## 贡献者类型

贡献可以包括：

- code
- docs
- templates
- eval samples
- tool contracts
- failure reports
- translations
- design discussions
- review notes
- usage reports

每类贡献都应可署名、可追踪、可复用，并保留修正机制。

## 决策流程

- 小型文档和模板改进可通过普通 PR 审查。
- 影响接口、事件、质量门禁、审批、安全、环境隔离或路线图的改动必须同步更新相关文档。
- 影响核心架构或治理规则的改动必须新增或更新 ADR。
- 涉及许可证、商标、官方兼容认证和项目方向的决策需要维护者和社区治理流程人工确认。
- 高风险自治能力必须先补 ApprovalGate、评测、审计和回滚设计。
- GovernanceBrain 生成的分派建议、模型路由建议和自我迭代候选不能替代维护者与社区治理流程。

## 商业公司参与规则

- 商业公司可以贡献和部署。
- 商业利益冲突需要披露。
- 商业发行版必须清楚标识来源、差异和兼容性。
- 企业不能通过资源优势改变个人和社区优先原则。
- 企业不能使用官方名称、Logo、兼容认证或官方发行版标识冒充官方。

## 商标与官方兼容声明

- 项目名称、Logo、官方兼容认证和官方发行版标识应由商标和治理规则保护。
- fork 可以存在，但不能冒充官方。
- 官方兼容认证必须定义测试范围、协议版本、撤销条件和公开名单。
- 商标策略和官方兼容认证仍需人工确认。

## 行为准则占位

后续应新增正式 Code of Conduct，至少覆盖：

- 尊重和包容。
- 反骚扰。
- 负责任披露安全问题。
- 禁止冒用身份。
- 冲突处理流程。

在正式文件落地前，维护者可按最小伤害、证据优先、透明记录和保护贡献者安全的原则处理社区冲突。

## 冲突处理

冲突处理应记录：

- 争议事项。
- 涉及贡献或实例。
- 相关证据。
- 利益冲突披露。
- 临时处置。
- 最终决定。
- 申诉或复审路径。

涉及安全、隐私、商标冒用或商业捕获风险时，应优先保护用户、贡献者和社区资产。

## 项目方向保护

以下变更需要特别审查：

- 将 AI-HRMS 限定回传统 HRMS。
- 将 AI-HRMS 改造成泛泛 agent framework。
- 默认上传用户私有数据。
- 绑定单一模型供应商、云平台或中心服务。
- 让跨实例协作绕过本地审批、审计和数据分级。
- 让资源降级绕过安全治理。
- 让 GovernanceBrain 替代人类 owner、自动批准高风险动作或隐藏建议来源。
- 让未评测的 ModelRoute 进入生产，或用模型能力强弱替代审批与数据分级。
- 削弱 Commons 资产、开放协议或贡献者署名。

## 社区实例之间的信任边界

- 默认不互信。
- 默认不共享私有数据。
- FederationLink 必须显式授权并可撤销。
- SharedEvalSummary 只能包含脱敏聚合信息。
- 高风险动作必须回到本实例 ApprovalGate。
- 跨实例通信必须审计。
- 被标记为 `blocked` 的 FederationPeer 不得继续协作。
