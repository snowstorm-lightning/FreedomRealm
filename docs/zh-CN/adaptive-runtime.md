# 自适应运行体系

## 为什么需要资源自适应

AI-HRMS 面向个人、社区、小团队和企业。不同用户的设备、预算、网络、模型可用性和治理要求差异很大。系统必须能在低配设备上解释核心抽象，也能在 Enterprise Mode 中运行完整治理栈。

自适应运行的目标是降低首次试用和长期个人使用门槛，同时保证资源降级不能绕过审批、安全、审计、预算和数据分级。

## 运行档位

| 档位 | 适用场景 | 运行特征 |
| --- | --- | --- |
| `Tiny Mode` | 低配设备、旧电脑、轻量试用和教学 | 文件存储或 SQLite，mock model、远程低成本模型或手动执行模式，单用户、低并发、最小 UI 或 CLI |
| `Demo Mode` | 首次体验 | 5 到 10 分钟跑通最小闭环，可用 SQLite、mock 工具、用户自带模型 API key，可生成 ExecutionReportCard |
| `Local Mode` | 个人长期使用 | 本地数据库，可选 Docker Compose，可选本地模型或远程模型，基础权限、基础审计、基础模板库和低成本模型路由 |
| `Community Mode` | 多人共用实例 | 多用户、角色权限、审批流、审计查询、模板共享、成员协作、资源配额、可选 FederationLink |
| `Enterprise Mode` | 企业、严肃组织和强治理场景 | Keycloak、Temporal、PostgreSQL、LiteLLM Proxy、OpenTelemetry、Grafana/Loki/Tempo/Langfuse、环境隔离、备份恢复和完整 ApprovalGate |

`Enterprise Mode` 保留现有强治理架构。Tiny、Demo 和 Local 不应反向削弱 Enterprise 的安全边界。

## ResourceProfile

系统启动时或配置时记录 `ResourceProfile`：

- CPU 核心数。
- 内存。
- GPU 可用性。
- 磁盘。
- 网络连通性。
- 本地模型可用性。
- 远程模型可用性。
- 用户预算。
- 并发上限。
- 隐私偏好。

ResourceProfile 是策略输入，不是安全豁免。

## AdaptiveRuntimePolicy

`AdaptiveRuntimePolicy` 根据 ResourceProfile 决定：

- 使用本地模型、远程模型、mock 模型或人工接管。
- 是否启用 embedding。
- 是否启用长期记忆。
- 是否启用完整观测。
- 是否启用并发 AgentRun。
- 是否降级为只读建议。
- 是否暂停高成本任务。
- 是否拆分任务。
- 是否要求人工确认。

所有决策必须写入审计或运行摘要。高风险任务不因资源不足绕过 ApprovalGate。

## Adaptive Model Router

自适应模型路由原则：

- 低配设备优先远程小模型或 mock。
- 有 GPU 的设备可使用本地模型。
- 高敏数据优先本地模型或摘要化。
- 成本超预算时降级模型、阻塞或转人工。
- 延迟超阈值时减少上下文、减少工具调用或拆分任务。
- 生产模型调用仍必须通过 `LiteLLM Proxy` 或等价受控 `ModelRoute`。
- 模型供应商只能作为 ModelRoute 或适配器，不能成为核心契约。

## Adaptive Task Scheduler

自适应任务调度原则：

- 低资源模式下限制并发。
- 高资源模式下允许批处理。
- 长任务可暂停和恢复。
- 预算耗尽后阻塞、降级或请求人工确认。
- 失败任务进入复盘和样本沉淀。
- 高风险动作进入 ApprovalGate，而不是因为队列积压自动批准。

## 低资源降级策略

低资源时可以：

- 关闭 embedding。
- 关闭长期记忆。
- 使用 mock/stub model。
- 使用手动执行模式。
- 将 agent 输出限制为只读建议。
- 限制工具调用次数。
- 降低并发。
- 暂停高成本任务。
- 请求人工接管。

低资源时不可以：

- 绕过 ApprovalGate。
- 跳过审计。
- 降低数据分级。
- 让远程模型接收敏感原文。
- 伪造工具成功。

## 高资源扩展策略

高资源时可以：

- 增加并发 AgentRun。
- 批量运行评测。
- 启用本地模型。
- 增加模板回放。
- 增强观测采集。
- 扩展长期记忆和知识索引。

扩展必须仍然受预算、策略、审批、审计和环境隔离控制。

## 成本预算

预算控制至少覆盖：

- 单次 WorkItem 成本。
- 单个 AgentRun 成本。
- 单个 AgentActor 日/月预算。
- 模型路由预算。
- 工具调用预算。
- ProjectInstance 预算。

超预算后可选动作是阻塞、降级、拆分或请求人工确认。

## 延迟预算

延迟预算至少记录：

- 首次启动时间。
- Demo 跑通时间。
- 单次任务平均延迟。
- P95 延迟。
- 工具调用延迟。
- 审批等待时间。

延迟优化不能删除必要审计，也不能默认批准审批。

## 本地模型与远程模型选择

- 高敏数据优先本地模型、摘要化或人工处理。
- 低敏、低风险、公开数据可使用远程低成本模型。
- 远程模型不可用时，按策略使用备用路由、mock、只读建议或人工接管。
- 本地模型不可用时，不得自动把敏感原文发送给远程模型。

## Mock/stub 模式

Tiny 和 Demo 可以使用 mock/stub：

- mock model。
- mock ToolContract。
- mock ApprovalGate 决策。
- 合成 WorkItem。
- 合成 Observation。

Mock 输出必须清晰标记，不能被当作生产事实。

## 人工接管

以下情况应转人工或阻塞：

- 预算耗尽。
- 模型不可用且无安全降级路径。
- 数据分级不允许当前模型路由。
- 工具输出不符合 schema。
- 任务风险高于当前运行档位能力。
- 审批超时或审批人不可用。

## 资源相关评测指标

- 首次启动时间。
- Demo 跑通时间。
- 最小内存占用。
- 最小磁盘占用。
- 单次任务平均 token 成本。
- P95 延迟。
- 低资源降级成功率。
- 本地模型可用率。
- 远程模型失败后的恢复率。
- 人工接管率。
- 资源预算命中率。

## 安全约束

自适应运行不能绕过：

- ApprovalGate。
- 安全治理。
- 审计。
- 预算控制。
- 数据分级。
- 环境隔离。
- 学习结果评测、审批、灰度和回滚。
