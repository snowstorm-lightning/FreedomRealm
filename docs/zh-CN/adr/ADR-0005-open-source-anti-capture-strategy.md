# ADR-0005: 开源反商业捕获组合策略

## 状态

Proposed

## 背景

FreedomRealm 优先服务个人和社区，但商业公司可以参与和使用。若只开放代码而缺少商标、协议、Commons 资产和治理规则，项目可能面临闭源 SaaS 吸血、封闭平台替代、品牌冒用和生态夺取风险。

许可证不能绝对阻止剽窃。本 ADR 记录组合策略方向，不构成法律意见。

## 决策

优先评估以下组合：

- 许可证候选优先评估 `AGPL-3.0`。
- 同时建立商标和官方兼容认证规则。
- 核心价值沉淀到开放协议、模板库、评测样本、ToolContract、Workflow Template、Skill Recipe、失败案例、复盘报告、实例协作协议和贡献者声誉。
- Commons 资产只接收用户明确发布的模板、工具契约、脱敏评测摘要、公开案例、失败样本和复盘报告。
- 用户私有数据、敏感数据、内部任务、非公开日志和原始模型上下文不得默认进入公共资产。
- 架构保持本地优先、实例自主、协议开放、供应商无关。
- 企业可以贡献、部署和参与讨论，但不能改变项目根目标。

许可证最终选择、商标策略和官方兼容认证需要维护者与社区人工确认。

## 许可证候选

- `AGPL-3.0`
- `Apache-2.0`
- `MIT`
- `MPL-2.0`
- 非标准 source-available 方案

采用非 OSI 开源许可证时，必须明确它属于 source-available 范畴。

## 后果

### 正面

- 降低闭源 SaaS 直接再封装风险。
- 保护官方身份和兼容认证。
- 将长期价值导向社区资产和贡献者声誉。

### 负面

- AGPL-3.0 可能降低部分企业采用意愿。
- 商标和认证需要持续治理成本。
- Commons 资产治理需要清晰贡献、署名、复用、修正和撤回机制。

## 替代方案

- 只采用 MIT 或 Apache-2.0：传播阻力低，但反捕获能力弱。
- 使用强限制 source-available：商业限制强，但不是 OSI 开源，可能削弱社区信任。
- 不做商标治理：fork 更容易冒充官方。

## 验证方式

- open-source-strategy 明确许可证候选、推荐方向、商标规则、协议生态、Commons 资产和企业参与边界。
- README 出现反商业捕获摘要。
- quality-gates 出现 Anti-capture gate。
- community-governance 出现商业公司参与规则和项目方向保护。
