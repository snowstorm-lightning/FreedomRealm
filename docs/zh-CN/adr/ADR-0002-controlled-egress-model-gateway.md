# ADR-0002: 采用受控出网 + 模型网关

## 状态

Accepted

## 背景

部署前提是企业内网强隔离，但允许受控出网。系统又要求供应商无关和后续本地模型挂载能力。

## 决策

- 所有模型请求统一走 LiteLLM Proxy
- 只有受控网段允许访问外部模型
- 外部模型访问受预算、策略、审计和路由规则控制

## 实施约束

- Agent Runtime、控制面和工具连接器不得直接持有生产模型供应商 key。
- 每个环境独立部署或独立配置 LiteLLM Proxy，模型 key、预算和路由不得跨环境复用。
- 模型调用必须记录调用方、模型、路由、耗时、成本、输入引用、输出引用和策略判断。
- `restricted` 与 `sensitive` 数据默认不得进入外部模型上下文，例外必须经过脱敏、摘要或审批。
- 模型路由变更属于生产策略变更，必须经过 staging 验证和 ApprovalGate。

## 后果

### 正面

- 保留模型供应商替换空间
- 统一审计、成本与限流
- 更适合未来接入本地 vLLM/Ollama

### 负面

- 网关成为关键基础设施，需要高可用与治理配置
- 某些供应商特性需要通过适配层暴露

## 验证方式

- 网络策略禁止运行面直连公网模型。
- 生产模型 key 只存在于生产网关 secret 中。
- 模型调用 trace 能关联 WorkItem、AgentRun、PolicyRule 和预算消耗。
- 关闭某个供应商路由时，系统能降级到备用路由或人工接管。

## 替代方案

- 各运行面直接访问模型：不满足治理要求
- 强绑定单厂商 SDK：不满足供应商无关目标
