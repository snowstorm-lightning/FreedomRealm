# AI-HRMS Web Workbench

This app is the Web-first onboarding surface for Demo Mode.

Current constraints:

- It is a static demo build.
- It reads data generated by the shared `packages/demo` execution layer.
- It must not duplicate CLI business logic.
- It must not require login, a live model key, an external connector, or real HR data.

Local command from the repository root:

```text
pnpm web:demo
```

The generated page is written to `dist/web/index.html`.

The current build renders seven built-in templates:

- `repo_understanding_and_work_plan`
- `knowledge_navigation_and_challenge`
- `external_agent_connector_safety_demo`
- `issue_pr_triage_and_review`
- `personal_work_proof`
- `project_self_review_and_decay_prevention`
- `docs_review_and_improvement`

Each template produces a canonical JSON `ExecutionReportCard` and a Markdown render under `dist/web/data/`.

The report preview keeps review evidence visible near the top of the card:

- canonical JSON source
- candidate eval samples and template `evaluationSamples`
- failure path sample
- `ApprovalGate`, data classification, redaction, and share boundary

These are review surfaces only. Markdown and Web views render the JSON report card; they do not become a second fact source.

The build also renders three built-in `Ask maintained docs` examples. Each example is generated by the shared knowledge/demo layer and writes:

- `AnswerCard` JSON
- `DocChallengeDraft` JSON
- `ExecutionReportCard` JSON / Markdown

`external_agent_connector_safety_demo` displays OpenClaw / Hermes Agent style runtimes as mock `ExternalConnector` profiles. It does not launch real external CLIs, read messaging accounts, load skills, access memory, call MCP servers, or read secrets.

`project_self_review_and_decay_prevention` displays self-review findings and candidate WorkItems in `ai-hrms.selfReview`. It does not create issues, PRs, assignments, or repository changes.
